# AI 规格（AI Specification）

> 本项目 MVP **不包含面向终端用户的 AI 功能**（无模型调用、无生成式 UI）。本文件界定「编码智能体」（ZCode 等）在本仓库中的受控协作方式，供后续任何 AI 会话遵循。

## AI 职责
- 按 TASK 文件实现/测试/调试/局部重构。
- 依据规格包回答与实现一致的问题；发现规格与代码不一致时报告而非擅自改规格。
- 维护 docs/PROJECT_STATE.md 与任务验收记录。

## AI 非职责
- 不决定产品方向、MVP 范围、重大架构（见 ARCHITECTURE 变更政策）。
- 不擅自引入/更换依赖、不触碰渠道 URL 等提供方配置之外的第三方服务。

## 智能体
### 智能体：编码智能体（任意会话）
目标：完成指定 TASK 的验收标准。
输入：docs/ 规格包 + docs/tasks/TASK-XXX.md + 现有代码。
输出：代码 + 测试 + PROJECT_STATE 更新 + 任务报告（变更文件/实现摘要/验证结果/遗留问题/架构影响）。
工具：文件读写、bash（pytest/vite/npm/git）、浏览器（UI 验证）。
护栏：AI_RULES.md 全文；架构冲突时 STOP 上报。

## 工具/命令
### COMMAND-001 task-implement
名称：实现任务
输入：TASK-XXX
校验：CODING_CHECK 清单 + 任务验收标准全部勾选
副作用：代码/测试/状态文件
回滚：git（每任务一提交，提交信息 `TASK-XXX: <目标>`）

## 结构化输出
- 任务报告必须包含五节（变更文件/实现摘要/验证结果/遗留问题/架构影响）。
- 验证结果必须粘贴真实命令输出摘要，不得声称未运行的检查。

## 对话流程
1. 读 PROJECT_STATE → 相关规格 → TASK。
2. 陈述实现计划与受影响模块。
3. 实现 + 测试。
4. 报告 + 更新 PROJECT_STATE。

## 人类审批点
- 重大架构变更（ARCHITECTURE 第 8 节）。
- 范围变更（新增/删除需求）。
- 发布（RELEASE_CHECK）。

## 失败处理
- 验证失败：修复后重跑；无法修复时如实报告并停在该任务，不伪造通过。
- 规格矛盾：STOP，按 AI_RULES「架构冲突」格式上报。

## 评估
- 准确性：验收标准逐条可勾选且证据可查。
- 安全性：无 shell=True 注入面、无令牌泄露、无越界路径写。
- 工具正确性：领域层测试不依赖 FastAPI/网络。
- 回归测试：缺陷修复必带回归用例。
