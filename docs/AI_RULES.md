# AI 规则（AI Rules）

## 编码之前

1. 阅读 docs/PROJECT_STATE.md 与本任务 TASK 文件。
2. 阅读受影响模块的规格（ARCHITECTURE / DOMAIN_MODEL / API_SPEC / TECH_SPEC）。
3. 检查现有代码模式（命名、目录、错误包络、测试风格）。
4. 向用户陈述实现计划与受影响模块。
5. 识别风险（进程安全、路径白名单、原子写、令牌脱敏是本项目四大高频风险）。

## 范围

只修改任务所需的文件。

禁止：
- 悄悄重新设计架构（模块边界/不变量/提供方边界变更 = 重大架构变更，先上报）
- 未经批准更换依赖库或引入新依赖
- 重写无关模块、顺手清理无关代码
- 为绕过报错而削弱类型（any/ignore/@ts-nocheck/裸 except）
- 删除或削弱测试
- 掩盖错误（吞异常、假数据、mock 冒充真实结果）
- 在日志/响应中输出完整令牌
- 使用 shell=True 拼接命令；绕过 core/paths.py 白名单写任意路径
- 在 backend/app/domain 中 import fastapi/httpx（领域层保持纯净）

## 本项目特定规则

- 一切持久化写操作必须原子（临时文件/目录 + rename），配置写后留 .bak。
- 进程状态迁移只能发生在 domain/process_supervisor 内部。
- 所有面向前端的守卫（运行中禁切换等）以后端为准，前端禁用仅为体验。
- 中文面向用户文案；代码注释仅在表达代码无法自明的约束时写。
- 提交信息格式：`TASK-XXX: <一句话目标>`；每任务至少一提交。
- Windows 开发环境注意：路径/权限相关测试须可在 Linux CI（AutoDL 真实环境）通过，优先在 WSL/Docker 验证再交付。

## 架构冲突

停下并报告：
- 冲突（规格条目 vs 现实）
- 原因
- 受影响模块
- 备选方案（≥2）
- 建议
- 迁移成本
等待用户批准后才继续。

## 验证

任务完成前运行必需的：
- 后端：`ruff check .` + `mypy app`（如配置）+ `pytest`
- 前端：`npm run type-check` + `npm run build`
- 涉及打包/脚本：`bash -n`（语法）+ shellcheck（如可用）
- UI 变更：构建后在浏览器实际走一遍对应页面状态（加载/空/错误/成功）

## 报告

报告（固定五节）：
- 改动内容（实现摘要）
- 涉及文件
- 验证结果（真实输出）
- 遗留问题
- 架构影响（无则写"无"）

## 完成的定义

只有验收标准和验证通过、PROJECT_STATE 已更新、无引入回归，任务才算完成。
