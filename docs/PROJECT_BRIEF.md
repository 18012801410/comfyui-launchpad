# 项目简报（Project Brief）

> 状态：待批准 ｜ 日期：2026-10-11 ｜ 来源：头脑风暴工作流（与用户逐题对齐）

## 产品

**ComfyUI LaunchPad（ComfyUI 启动台）** —— 一个运行在 AutoDL GPU 实例内的 Web 控制面板，面向公众发布。用户在自己租用的 AutoDL 实例上通过一键脚本安装，即可在浏览器里完成 ComfyUI 的启动/停止、参数配置、多版本切换、插件更新、工作流导入和系统状态监控。

参照产品：ZEALMAN ComfyUI Control Panel 3.0（https://uu788723-791533bb2de0.bjb2.seetacloud.com:8443/ ）。本产品第一版只做其「启动器核心」部分，生成类功能留待二期。

## 问题

AutoDL 上的 ComfyUI 用户（尤其新手）面临：

1. **启动门槛**：需要命令行激活环境、记忆启动参数、手动挂学术加速，新手容易卡住。
2. **版本管理困难**：升级/回滚 ComfyUI 版本直接操作 pip 环境，容易搞坏且不可逆。
3. **状态不可见**：GPU/驱动/显存/内存/磁盘/进程状态分散在不同命令里，没有直观呈现。
4. **工作流获取难**：好用的 workflow JSON 散落各处，导入本机 ComfyUI 操作繁琐。

## 目标用户

在 AutoDL 租用 GPU 实例运行 ComfyUI 的公众用户：从「刚开第一台实例」的新手，到「多版本切换、参数调优」的中度玩家。单一管理员（实例 owner）使用，无多用户账号需求。

## 核心用户流程

1. 用户在 AutoDL 实例的 SSH/JupyterLab 终端执行一条一键安装命令 → 脚本安装面板并启动，打印访问地址与访问令牌。
2. 浏览器打开面板（AutoDL 6006 端口映射的公网 HTTPS 域名），输入令牌进入。
3. 在「版本管理」页选择并安装一个 ComfyUI 版本（自包含版本包，下载解压）。
4. 回到首页勾选学术加速、确认启动参数 → 点击「启动 ComfyUI」→ 观察实时日志直至就绪。
5. 点击「打开 ComfyUI →」跳转本机 8188 的 ComfyUI 界面开始创作。
6. 在「工作流管理」页从官方库一键导入工作流，或上传自己的 JSON；在「插件管理」页一键更新插件。
7. 面板提示新版本时，一键自升级。

## MVP 范围

### 必须有

1. **一键安装/卸载脚本**：可重复执行、幂等；安装完成打印访问地址与令牌；卸载不删用户数据（models/output/工作流）。
2. **ComfyUI 进程控制**：启动/停止/重启、实时日志流、学术加速开关（启动前 source AutoDL 加速脚本，失败优雅降级直连）、启动参数编辑 + 显存优化预设（--lowvram/--medvram/--fp16/vram 状态等）、监听端口设置。
3. **系统状态监控**：GPU 型号/驱动版本/显存占用、内存、磁盘、CUDA 可用性、ComfyUI 进程状态。
4. **多版本管理**：可用版本列表（来自 GitHub Releases 元数据）、下载安装（自包含版本包）、符号链接 `current → vX.Y.Z` 秒级切换、删除；ComfyUI 运行中禁止切换。
5. **数据共享布局**：models/output/input 置于 autodl-tmp 共享目录（extra_model_paths.yaml），版本切换不丢数据。
6. **插件管理（轻量）**：扫描 custom_nodes 生成列表（名称/远程地址/更新状态）+ 一键更新（git pull）。
7. **工作流管理**：官方工作流库（作者维护的独立分发渠道，索引 JSON + 工作流文件）浏览/刷新/一键导入到本机 ComfyUI 工作流目录；用户本地上传 JSON；已导入列表与删除；导入时解析并提示依赖的模型清单（不自动下载）。
8. **面板自升级**：检查新版本 → 下载 → 解压替换 → 自重启；保留上一版目录，失败自动回滚。
9. **安全与设置**：安装时生成随机访问令牌，所有 API 与页面强制令牌校验；可修改令牌；明暗主题。

### 应该有

- 安装完成后的自检（端口占用、Python 版本、磁盘余量提示）。
- 版本包下载进度与断点续传提示。
- 面板运行日志页（排查面板自身问题）。
- 「打开 ComfyUI」按钮自动探测就绪状态后启用。

### 范围外（明确不做）

- 一切生成功能：快捷生成、图像生成、简易画布、API 生成、并发生成、任务队列、我的资产（二期）。
- 工作流所需模型/节点的自动下载与安装（仅提示依赖清单）。
- 插件市场/搜索/依赖修复。
- 多用户与账号体系（单管理员令牌）。
- 远程开关机等 AutoDL API 集成。
- Windows/macOS 本地环境（仅 AutoDL Ubuntu 容器）。
- ComfyUI 工作流编辑器（ComfyUI 自带）。

## 约束

- **运行环境**：AutoDL Ubuntu 容器（无 systemd、无 root 外权限差异，Python ≥3.10，镜像通常自带 miniconda + CUDA/torch）；公网入口为 AutoDL 映射端口（6006 为文档保证的自定义服务端口，HTTPS）。
- **技术栈**：后端 Python FastAPI（单进程同时提供 API 与打包后的静态页面），前端 Vue 3 + Vite。CI 用 GitHub Actions 打包版本包并发布到 GitHub Releases。
- **分发方式**：一键脚本安装（wget/curl + bash）；版本包与官方工作流库均经 GitHub Releases 分发（国内访问依赖 AutoDL 学术加速）。
- **网络现实**：实例直连 GitHub 慢或不通，学术加速是关键依赖，必须可降级。
- **磁盘现实**：系统盘 30GB 起且计费，版本包与大文件必须落 autodl-tmp（数据盘）。

## 决策

| # | 决策 | 选择 | 被否掉的备选及原因 |
|---|---|---|---|
| 1 | 用途定位 | 面向公众发布（类 ZEALMAN），需要自升级、容错、安装便捷 | 仅自用（不需要稳定性和分发投入）；小团队分享（标准降低） |
| 2 | MVP 范围 | 只做启动器核心（含版本切换、轻量插件、工作流管理） | 启动器+生成（需调通 ComfyUI 工作流 API，周期长）；全功能对标（工程量过大） |
| 3 | 版本包策略 | 方案 A：CI 打包自包含版本包（代码+锁定依赖，torch 复用镜像环境）→ GitHub Releases → 下载解压 → 符号链接切换 | B 现场安装（pip 现装慢、易失败，公众体验不可控）；C 云端控制面（MVP 用不上，运维重） |
| 4 | 数据共享 | models/output/input 指向 autodl-tmp 共享目录 | 每版本独立数据目录（丢模型、浪费空间） |
| 5 | 进程管理 | 面板后端直接 spawn ComfyUI 子进程（进程组 + 日志管道） | systemd（容器内不可用） |
| 6 | 面板端口 | 默认 6006（AutoDL 自定义服务文档保证映射），安装参数可改；ComfyUI 跑本机 8188 | 8443（参考面板用法，但非 AutoDL 文档保证端口） |
| 7 | 安全 | 安装时生成随机访问令牌，API+页面强制校验 | 无鉴权（公网映射端口裸奔，任何人可控制实例） |
| 8 | 插件管理 | 轻量：列表 + 一键 git pull 更新 | 完整插件管理（与 ComfyUI-Manager 定位重叠，工程量大） |
| 9 | 面板自升级 | 进 MVP：检查→下载→替换→自重启，保留回滚目录 | 脚本重跑升级（体验差）；只提示不自升级（公众工具修 bug 困难） |
| 10 | 工作流分发 | 独立工作流库 Release 渠道（索引+文件），面板运行时拉取；作者新增工作流只需发库版本，无需发面板版本 | 工作流内置进面板包（失去作者后期添加的灵活性） |
| 11 | 技术栈 | FastAPI + Vue 3 + Vite；GitHub Actions CI | FastAPI+React（无显著优势）；Go 单二进制（与 Python 生态割裂）；纯 Python 无前端框架（UI 质量受限） |
| 12 | 名称 | ComfyUI LaunchPad（ComfyUI 启动台） | — |

## 成功标准

1. 一条命令完成安装，全程无需人工干预，安装产物可幂等重装。
2. 新手用户 5 分钟内从零完成：安装面板 → 装一个版本 → 启动 ComfyUI → 在浏览器打开 ComfyUI。
3. 版本切换在 ComfyUI 停止状态下 10 秒内完成且可回滚，模型/输出数据不丢失。
4. 官方工作流库新增工作流后，用户端刷新即可导入，无需重装面板。
5. 面板自升级一键完成，失败可自动回滚到旧版本继续可用。
6. 面板在公网暴露端口下无未授权访问（令牌强制）。

## 待定问题（Open Questions）

1. **是否开源**面板代码（建议开源以建立公众信任；影响发布与贡献流程）——待用户决定。
2. **版本包双发 AutoDL 共享目录**（类 ZEALMAN 的符号链接解压免下载方案）：MVP 先 GitHub Releases，二期评估。
3. **开机自启机制**：AutoDL 容器无 systemd，官方自启动方式需在规格阶段核实；兜底方案是安装完成提示用户在控制台配置启动命令。
4. **torch 兼容矩阵**：各 ComfyUI 版本对 torch 的最低要求需在 CI 打包设计时调研确定，个别版本可能需要包内附带 torch 升级脚本。
5. **官方工作流库首批内容**：由作者提供，规格阶段确定工作流元数据格式（名称/预览图/依赖模型清单/分类）。
6. **面板默认端口**在 6006 被占用时的行为（自动顺延 or 提示用户改）——规格阶段定。
