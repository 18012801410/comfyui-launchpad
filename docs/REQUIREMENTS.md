# 需求规格（Requirements Specification）

> 上游：docs/PROJECT_BRIEF.md（已批准）｜ 日期：2026-10-11

## 产品目标

让 AutoDL 上的 ComfyUI 用户在 5 分钟内从「裸实例」到达「浏览器里用上 ComfyUI」，并且之后的版本切换、插件更新、工作流导入都能在图形界面里一键完成，不碰命令行。

## 用户画像

- **新手小王**：第一次租 AutoDL 实例，会开 JupyterLab 但记不住任何 Linux 命令；怕把环境搞坏。
- **中度玩家阿珍**：会基本命令行，关注版本更新与显存优化参数，需要多版本来回切。
- **作者（你）**：面板与官方工作流库的维护者，需要低成本发布更新与新工作流。

## 用户故事

### US-001
作为一个新手用户，我想要一条命令安装面板，以便不学 Linux 就能用上控制面板。

### US-002
作为一个用户，我想要在网页上点一个按钮启动/停止 ComfyUI，以便不用记激活环境和启动命令。

### US-003
作为一个用户，我想要实时看到 ComfyUI 的启动日志，以便知道它是否正常起来了、出错在哪。

### US-004
作为一个用户，我想要看到 GPU/驱动/显存/内存/磁盘/进程状态，以便确认实例资源够用、运行正常。

### US-005
作为一个用户，我想要在列表里挑选并一键安装某个 ComfyUI 版本，以便升级/降级不用手工操作 pip。

### US-006
作为一个用户，我想要秒级切换版本且模型和输出不丢，以便多版本之间来回试。

### US-007
作为一个用户，我想要编辑启动参数和使用显存优化预设，以便在大模型爆显存时自己能解决。

### US-008
作为一个用户，我想要一键开关学术加速，以便下载模型和访问 GitHub 更快。

### US-009
作为一个用户，我想要看到已装插件列表并一键更新，以便插件保持最新而不用学 git。

### US-010
作为一个用户，我想要从官方工作流库浏览并一键导入工作流，以便直接用上作者维护的成品工作流。

### US-011
作为一个用户，我想要上传自己的工作流 JSON 到面板管理，以便统一存放和快速取用。

### US-012
作为一个用户，我想要面板提示新版本并一键自升级，以便始终用上修好 bug 的最新面板。

### US-013
作为一个作者，我想要通过发布工作流库版本向所有用户新增工作流，以便不用重发面板。

### US-014
作为一个公网暴露面板的用户，我想要面板强制访问令牌，以便只有我能控制我的实例。

## 功能需求

> 优先级：P0=MVP 必须；P1=MVP 应该有。所有 FR 默认依赖 ARCH-00x 架构承载，仅列直接依赖。

### FR-001 一键安装与卸载
描述：提供 `install.sh`（curl/wget + bash 执行）与 `uninstall.sh`。安装脚本：检测环境（Python≥3.10、磁盘余量、6006 端口占用）、下载面板发行包、安装到 `/root/launchpad/`（面板自身）、生成随机访问令牌、注册 `~/.bashrc` 自启片段（幂等、可 `LAUNCHPAD_NO_AUTOSTART=1` 跳过）、启动面板、打印访问地址+令牌。卸载：停进程、删面板目录与 bashrc 片段，**不删** `/root/autodl-tmp` 下的数据目录。
优先级：P0
验收标准：
- [ ] 全新实例上执行一条命令，90 秒内完成安装并打印可访问的 URL 与令牌
- [ ] 重复执行安装脚本幂等（升级式覆盖，令牌与配置保留，除非 `RESET=1`）
- [ ] 卸载后 models/output/input/工作流目录完整保留

### FR-002 ComfyUI 进程控制
描述：面板后端以子进程方式启动/停止/重启 ComfyUI（进程组管理）。启动前按配置拼接命令行参数；启动后采集 stdout/stderr 写入环形日志缓冲；停止发送 SIGTERM，超时（10s）升级 SIGKILL。前端可启停、重启、查看实时日志（SSE/WS 推送）。
优先级：P0
验收标准：
- [ ] 点击「启动」后日志实时滚动，进程状态从 stopped → starting → running 准确流转
- [ ] 停止后 10 秒内进程与子进程全部退出，状态回 stopped
- [ ] 重复点「启动」被拒绝并提示已在运行；停止不存在的进程不报错
- [ ] 面板重启后能正确识别遗留 ComfyUI 进程并纳入管理（状态对账）

### FR-003 启动参数与预设
描述：用户可编辑启动参数（监听端口、--listen、显存优化 --lowvram/--medvram/--novram/--fp16 等），提供「默认/低显存/极速 FP16」等预设一键填充。参数持久化，下次启动生效。启动前校验端口占用。
优先级：P0
验收标准：
- [ ] 预设一键填充后参数可见、可再编辑、保存后重启生效
- [ ] 非法参数（非数字端口、注入字符）被拒绝并给出原因

### FR-004 学术加速开关
描述：开关状态持久化。启用时启动 ComfyUI/下载版本包/更新插件前 `source /etc/network_turbo`，禁用或加速失效时直连。面板显示当前代理环境状态。
优先级：P0
验收标准：
- [ ] 开关即时持久化，对下次启动/下载生效
- [ ] 加速源不存在或超时时自动降级直连，日志可见提示，操作不失败

### FR-005 系统状态监控
描述：采集并展示：GPU 型号/数量/驱动版本/显存总量与占用（nvidia-smi）、内存总量与占用（含 cgroup 限额与宿主机值）、系统盘与数据盘用量、CUDA 可用性、ComfyUI 进程状态。前端轮询（5s）+ 主动刷新。
优先级：P0
验收标准：
- [ ] 各卡片数据与 `nvidia-smi`/`free -h`/`df -h` 人工核对一致
- [ ] 任一采集源失败时对应卡片显示「不可用」而非整个页面报错

### FR-006 版本管理
描述：面板从版本索引（GitHub Releases 的 index.json）拉取可用 ComfyUI 版本列表；下载自包含版本包（tar.zst）到 `/root/autodl-tmp/launchpad-data/versions/<ver>/`；安装完成后 `current` 符号链接指向新版本完成切换；可删除非当前版本；ComfyUI 运行中禁止切换/删除。显示下载进度。已装列表、当前版本、面板推荐版本可见。
优先级：P0
依赖：FR-004（加速）
验收标准：
- [ ] 全新实例安装一个版本 ≤ 5 分钟（4090 实例 + 加速，视网速）
- [ ] 切换（已装版本间）≤ 10 秒，`current` 指向正确，启动的是对应版本
- [ ] 运行中切换/删除按钮禁用并提示；删除当前版本被拒绝
- [ ] 下载中断后重试不产生半成品版本（原子解压：先落临时目录再 rename）

### FR-007 数据共享布局
描述：ComfyUI 的 models/output/input/user 通过 extra_model_paths.yaml 与目录符号链接指向共享数据目录 `/root/autodl-tmp/launchpad-data/shared/`，全部版本共用；安装版本包时自动建立该布局。
优先级：P0
验收标准：
- [ ] 切换版本后 models 里模型列表不变；生成输出始终落在共享 output
- [ ] 共享目录结构在版本安装/删除/切换后保持一致

### FR-008 插件管理（轻量）
描述：扫描当前版本的 custom_nodes/，展示插件名、简介（读 pyproject.toml/README 摘要）、git 远程与版本、更新状态；一键更新 = git pull + 提示依赖变化；可禁用/启用（目录改名 `.disabled` 后缀）。不做市场/搜索。
优先级：P0
验收标准：
- [ ] 列表与 custom_nodes 实际内容一致
- [ ] 更新失败（冲突/无远程）时给出明确原因，插件保持可用
- [ ] 禁用后重启 ComfyUI 该插件不加载，启用后恢复

### FR-009 工作流管理
描述：双来源。①官方库：拉取工作流库索引（独立 Release 渠道），卡片展示（名称/封面/分类/依赖模型清单/更新时间），一键导入 = 复制 JSON 到当前版本工作流目录并登记；「刷新」重新拉索引。②本地上传：上传 JSON，校验格式后入库。已导入列表可查看/删除/重新导入。导入时解析 JSON 列出依赖的 checkpoint/lora 等模型清单并标注本机是否已存在（不自动下载）。
优先级：P0
依赖：FR-004
验收标准：
- [ ] 作者发布新工作流库版本后，用户端「刷新」即见新工作流，无需更新面板
- [ ] 导入的工作流能在 ComfyUI 界面的工作流列表中打开
- [ ] 上传非 ComfyUI JSON 被拒绝并说明原因
- [ ] 依赖清单正确区分「已存在/缺失」，缺失项给出模型名与建议放置目录

### FR-010 面板自升级
描述：面板检查自身新版本（Release 元数据）→ 展示更新日志 → 一键升级：下载新发行包 → 解压到新目录 → 停自身服务前启动接管脚本 → 原子切换符号链接 → 自重启 → 健康检查；失败自动回滚到上一版本目录。升级保留用户配置与令牌。
优先级：P0
验收标准：
- [ ] 升级全程 ≤ 2 分钟，期间 ComfyUI 进程不受影响
- [ ] 升级失败（下载损坏/启动失败）自动回滚，面板恢复可用，明确提示
- [ ] 升级后版本号正确，配置与令牌保留

### FR-011 访问令牌鉴权
描述：安装时生成 32 字符随机令牌；所有 API 请求与页面访问须携带令牌（首访输入一次存 localStorage；API 用 `Authorization: Bearer`）；可查看/重新生成令牌（重新生成后旧令牌立即失效）。日志/响应中令牌永不回显全文。
优先级：P0
验收标准：
- [ ] 无令牌访问任意 API 返回 401；页面跳转到令牌输入页
- [ ] 重新生成令牌后旧令牌 401
- [ ] 令牌不出现在任何日志与错误信息中

### FR-012 面板运行日志
描述：面板自身的操作日志（启动/下载/升级/进程管理事件）可查看与下载，便于用户报障与作者诊断。
优先级：P1
验收标准：
- [ ] 日志包含时间戳、级别、模块，可按级别过滤，可下载完整文件

### FR-013 安装自检
描述：安装完成后自动自检：Python 版本、端口占用、磁盘余量（<10GB 警告）、GPU 可见性、数据盘挂载，结果汇总打印并在面板「系统设置」页可重跑。
优先级：P1
验收标准：
- [ ] 每项检查有明确通过/警告/失败输出与修复建议链接

### FR-014 明暗主题与基础设置
描述：明/暗主题切换（跟随系统为默认）；语言仅中文（MVP）；系统设置页含令牌管理、自启开关、主题。
优先级：P1
验收标准：
- [ ] 主题选择持久化，刷新后保持

## 非功能性需求

- **性能**：面板 API P95 < 300ms（不含下载）；日志流延迟 < 1s；状态页轮询对 CPU 占用 < 2%。
- **安全**：默认令牌鉴权强制；所有下载校验 SHA-256；子进程以实例用户运行、无提权；路径参数严格校验防目录穿越。
- **可靠性**：面板进程崩溃退出后可被 bashrc 自启拉起；ComfyUI 异常退出状态准确回 stopped；所有写操作原子（临时目录+rename）。
- **兼容性**：AutoDL 基础镜像（Ubuntu 20.04/22.04，conda Python 3.10/3.11，CUDA 11.8/12.1+）；不依赖 systemd；面板自身依赖仅限制在标准 pip 可装范围内。
- **可扩展性**：版本渠道、工作流渠道均为可配置 URL（作者后期可换 CDN/镜像源）；生成类功能二期接入时新增模块，不动启动器核心。
- **资源占用**：面板自身常驻内存 < 150MB，不占 GPU。

## MVP 边界

### 包含
FR-001 ~ FR-011（P0 全部）+ FR-012/013/014（P1，随能力顺延不阻塞发布）。

### 排除
见 docs/PROJECT_BRIEF.md「范围外」：生成功能全家桶、模型自动下载、插件市场、多用户、AutoDL API 集成、非 Linux 环境、工作流编辑器。

## 边界情况

- 6006 被占用：安装脚本自动顺延探测可用端口（6006→6008→…）并打印实际端口。`[AI-DECIDED]` 自动顺延而非仅提示。
- 实例无数据盘（未挂载 autodl-tmp）：安装失败并提示先在控制台添加数据盘。
- 用户直接在命令行 kill 面板：bashrc 自启兜底；手动重启脚本 `launchpad restart`。
- 版本包索引不可达：展示缓存的上次索引并标注时间；无缓存则明确报错与排查指引。
- ComfyUI 启动即崩（缺模型/参数错）：日志页高亮 ERROR 行，状态标 failed 并保留退出码。
- 同一浏览器多人拿到 URL：令牌即唯一凭证，泄露可在设置页重置。
- 磁盘写满：下载/安装前预检剩余空间（包大小×1.2），不足则拒绝并提示清理。
- 面板与 ComfyUI 同时升级冲突：自升级前若 ComfyUI 运行中，询问用户（默认继续，互不影响）。
